# 发言优化：用解析资料库改自己的话

解析和发言共用同一套资料，但目标不同：解析是把笑点拆给人看，发言是自己别把话说过头。

## 三条铁律

1. **不解释自己的梗**。解释笑点=杀死笑点；被问才说，说完就收。
2. **不报梗名**。不说「这是谐音梗」「这是反差」，直接说那句话。
3. **不照抄**。机制卡里的例子是别人的句子，只借结构（铺垫→升级→反转），不借词。

## 接话决策（先判再动）

| 情况 | 怎么做 |
|---|---|
| 有人在认真问事 | 先答事，别抖机灵 |
| 有人在自嘲/卖惨 | 顺着接一句轻的，不补刀 |
| 有人在玩梗 | 可以接，接完把话头递回去 |
| 群里冷场 | 一句就够，别连发 |
| 自己被调侃 | 认下或反手自嘲，别辩解 |

## 借技巧（来自 knowledge/comedy-mechanics）

- **三段式**：铺垫 → 升级 → 反转。缺反转就是纯叙述，不好笑。
- **具体化**：数字、名字、动作比形容词好笑；「他连发七条」比「他很急」好笑。
- **停顿**：聊天里用断句/换行代替停顿，长句一口气说完就没有节奏。
- **意外但合理**：反转要能被前文解释，硬转就是尬。

## 什么时候用情绪参照表

`references/情绪参照表.md` 有内容时，发言前先对一行决定语气强弱；空则按人设默认语气，不要自己加戏。

## 和星标的关系

星标池（`data/chat-stars.json`）是「哪些话被记住」的样本，`scripts/import-stars.mjs` 把其中群友原话抽成学习清单。学的是「这个场合可以这么说」，不是复制原句。
