## 提示词写法与撤回规矩（2026-11-06 主人定）
- **所有提示词必须写成 flash（`glm-4.5-flash`）能理解的写法**：一条规则一句；禁令单独成行且「不许/别」放句首；条件写「如果…就…」；抽象词换可观察动作；她写的 `举例：` 例句逐字不改；等价改写不删规则、不加规则、不增字数。详见 `名词解释/名词解释.md` §106。
- **她会在客户端里同步改人设**：改人设前必须重读当前磁盘内容，不能拿旧快照整文件覆盖；优先逐句精确替换。2026-11-06 22:45 她改过 `1-性格.md`、`2-说话.md` 的「不知道就说不知道」→「没把握先查、查不全讲已知给方向」，并删了 3 个旧例句。
- **「不让提示词变多」不是否决理由**（她 2026-11-07 纠正）：含义是「能用代码做的功能不许写成提示词」+「写提示词时用最少写法」，不是字数不许增加。情绪数值状态、语气生成这类都由代码算，只有代码生成的最少行语气句进提示词。禁止再以「会加几行提示词」为由否决方案。
- **被撤回的消息不进风格样本**：撤回自动清样本 + 加一条待修复问题；聊天记录不自动删。
- **待修复问题复用 `src/data/ai-feedback.jsonl`（kind='待修复'）**，不建平行文件；客户端聊天记录页可手动标错 + 移除该条记录。
- `tests/test-all.js` 必须 `cd src && node ../tests/test-all.js` 跑（脚本内用相对路径 `data/`）；在项目根跑会让快照/还原落空并污染 `src/data/topics.jsonl`，且它依赖本机 8799 面板服务，连不上会中途 FAIL。
