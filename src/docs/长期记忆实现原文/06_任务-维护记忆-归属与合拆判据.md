# 任务-维护记忆｜改动记忆文件时读
# 触发：新增/修改/删除记忆条目、记忆文件变长、要判断某条该放哪

> 这是给 AI 看的操作规范，不是给人看的说明书（人看的在 `../记忆一览.md`）。

## 一、归属：先看触发面，再看后果（两维，顺序不能反）

**只问“不知道会犯什么错”不够**——那会把「页游数值记错」这种后果严重、但只在聊那个游戏时才可能发生的规则塞进常驻，白付 token。所以先判**触发面**，再在触发面之内排后果。

**第一步：不碰这件事，我有没有机会踩？**
- 不聊这个游戏 / 不动这个项目 → 永远不会踩 → **按需**（放 `话题-X` / `任务-X`）。**后果再重也不进常驻。**
- 任何对话、任何任务都可能踩 → 进第二步。

**第二步：踩了会怎样？**
- **不可逆**（删错文件、泄露凭证、发错消息）或**要返工**（方向做反、写完再重写）→ **常驻**
- 只是**答得糙一点**、多问一次、引得不够准 → **删**，或压成一句留在常驻

**判据示例（拿真实规则验，能分开才算判据成立）**

| 规则 | 触发面 | 后果 | 判定 |
|---|---|---|---|
| 不删好功能 | 宽·任何改动 | 不可逆 | 常驻 ✔ |
| 凭证不读不打印 | 宽·任何调试 | 不可逆（泄露） | 常驻 ✔ |
| 弹窗禁用原生 `alert` | 宽·任何页面 | 要返工 | 常驻 ✔ |
| `.command` 的 `mktemp` 写法 | 宽·任何 mac 脚本 | 要返工 | 常驻 ✔ |
| 页游数值 `1~15/0~31/255` | 窄·不聊洛克就不会踩 | 严重 | 按需 ✔（旧判据会误判常驻） |
| 四池 `90/8/2/500` | 窄·不碰这项目就不会踩 | 严重 | 按需 ✔ |
| 巡视三概念辨析 | 窄·不聊时政就不会踩 | 答得糙 | 按需 ✔ |

**反向自检（对常驻逐条问）**：跟她聊一件完全无关的事时，这条会用上吗？答「不会」→ 它该挪走，不管它多重要。

**两条禁用判据**：
- **禁用使用频率**：规则多为防御性，平时用不上、出事那一刻才用。按频率判会把「不删好功能」这类挪出常驻。
- **禁用字数**（2026-11-01 废除字数阈值）：长而常用的留，短而没用的照样挪。

**一条豁免（必须留，否则判据会害事）**：
> 触发面窄、但**只占一行、后果不可逆**的硬红线，**可以留常驻**。
> 理由：按需文件只有在「我认出该读它」时才生效；触发识别一旦失败，规则就等于不存在。省几十字的收益，抵不上一次触发失败的代价。
> 判豁免的标准只有一条：**这行 ≤ 30 字 且 踩了不可逆**。两者缺一就照常挪。

**为什么必须有这条**：2026-11-01 实测拿新判据过全部常驻，`.command` 写法、测视觉用真图、接 API 不接逆向、禁原生弹窗这 4 条触发面都窄，本该全挪走——但它们是「一次踩中就要重做/封号」级别，且加起来才约 120 字。挪走的净收益是负的。

## 二、合与拆

**合（优先）**：总在同一次活里一起用到的规则 → 必须**同一文件、相邻放**。
- 禁一条规则的上半句在 A 文件、下半句在 B 文件。**散落比重复更糟**——重复至少读得到，散落两边都不完整。
- 禁为「分类好看」把一条完整规则切开塞进两个文件。

**拆**（只在一种情况下）：
- 永远整份读 → **不拆**，再长也不拆。
- A 场景只读第 1 节、B 场景只读第 3 节 → **拆**。

**膨胀的真正信号**：打开这份文件，要**跳过一半以上**才找到当下要用的那条 → 该拆。字数只是相关性，不是判据。

## 三、冗余判定

**同一条规则有第二个「家」就是冗余，与长短无关。**
- 处理：留主文件那处完整版，别处一律改成 `见 <文件名>`，不重述内容。
- 「换个说法讲同一件事」也算冗余（脚本会按相似度抓）。

## 四、每次改完记忆必做

1. 跑检查脚本（本地 Python，不联网、不调模型、不耗积分）：
   ```bash
   python3 "/Users/zhengbowen/.workbuddy/user-4641772a-9652-455b-9085-ab314b5df106-personal/检查冗余.py"
   ```
2. 报告里出现**同一句两处** → 当场合并，报告「已合并：A↔B，留 X」。
3. 报告里出现**疑似散落**（同一主题的两半在两个文件）→ 合到主文件。
4. 新增前先 grep 关键词查有没有旧条目：有 → 改旧的；同类 → 并进那条。**不许新增平行条目。**
