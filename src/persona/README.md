# 人设包说明

> 本目录是**索引 + 快照**，不是正文。正文在 `src/soul/` 和 `src/data/`，全项目只有那一份。
> `1-人设正文/`、`6-记忆数据/` 下的是**软链接**：点开、编辑，改的就是真身。

## 一、人设由 5 层组成

| 层 | 内容 | 真身位置 | 会被什么改掉 |
|---|---|---|---|
| 1 人设正文 | 身份、我自己的口味、性格、说话、应对（5 份）＋应对场合段 3 份 | `src/soul/虚幻.md`（入口）+ `src/soul/段/0-我的喜好.md`、`1-性格.md`、`2-说话.md`、`3-应对.md`；场合专属段在 `src/soul/应对/` | 人改（面板改完下一句生效） |
| 2 口味/风格/梗库 | 见第二节表 | `src/data/` 下同名文件 | 机器自动写（每 15 条样本重写一次风格） |
| 3 固定提示词 | 13 段硬编码 | `src/core.js` 的 `systemPrompt()`（569 行起） | 只有改代码 |
| 4 动态注入 | 按情况注入 | `src/core.js` 的 `buildMessages()`（3256 行起）+ `src/connectors/qq.js` | 只有改代码 |
| 5 发送前过滤 | 禁括号、拆段、复读白名单、剥 @ | `src/core.js` 的 `polish()` + `src/connectors/qq.js` | 只有改代码 |

**人设 5 份怎么拼**：`readSoul()` 按「入口 → 0-我的喜好 → 1-性格 → 2-说话」的顺序读全文拼成一份；
`3-应对.md` 不在这里拼，它由 `readResponseBlocks()` 按「公共 / 我 / 别人」三块切开，按这一轮谁在说话挑块注入。
2026-11-07 起，应对的场合专属段物理分离到 `src/soul/应对/`（我-被夸 / 我-被怪 / 别人-被围观各一份），
由 `RESP_SCENES` 命中才注入。`<!-- -->` 注释不进提示词。
AstrBot 插件（`astrbot_plugin_persona_share`）读同一目录、同样顺序。
少一份，那段规矩就整段没有——自检会报。

**口味分两张表**：主人自己的（主人＝虚幻一体）在 `soul/段/0-我的喜好.md`，人设层，跟「我是谁」一起注入；
别人的在 `data/人物喜好.md`，一人一节、按好感度排。`taste.js` 按 QQ 判断该写哪张，两边不混。

## 二、第 2 层的真身对照

| 本包文件 | 真身 | 谁在写 |

| `1-人设正文/0-我的喜好.md` | `src/soul/段/0-我的喜好.md` | 机器人（主人说的进「喜欢/讨厌」，提过没表态的进中立） |

## 五、换框架时怎么用

1. 人设正文：`soul/虚幻.md` + `soul/段/` 三份，按序拼成一份
2. 口味/风格/梗库/攻略：`src/data/` 下同名文件原样搬
3. 固定段：按 `3a` → `3b` → `3c` 的顺序拼进 system prompt
4. 动态段：`4a`（每轮）→ `4b`/`4c`（按情况）→ `4d`（连接器）写成插件规则
5. 公共规则层：写成发送前过滤器

## 六、注意

- 不要在本目录新建同名副本——一建就又变成两份，必然漂。要改就改真身。
- 别在面板里给这些链接改名或删除：那删的是链接本身，不是真身；真身还在，但这里会缺一格。
- 本包不含密钥、聊天流水、表情图片本体。
