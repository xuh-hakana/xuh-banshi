## 0 一句话结论

不新建六套系统。项目里已经有 5 个模块在干这六条里的大部分事（`people` / `taste` / `style` / `guides` / `memory`），
**再各建一套就是六份平行系统**，违反「同功能并进老处」的铁律。

本方案只做三件事：

1. 新增一个**编排层** `src/learn/`（8 个文件，全部薄），把六条要求挂到既有模块上；
2. 新增一个**存储根** `src/data/learn/`（按人员物理隔离、按月切、可导出、可版本化）；
3. 在 `core.js:4292 buildMessages()` 里加**一个**注入调用（热层），不散着加。

既有的 `memory.longForPrompt()`、`taste.block()`、`style.block()`、`guides.search()` 一个都不删、不改签名。

## 2 三层架构 → 具体代码位置

| 层 | 内容 | 什么时候读 | 预算 | 落点 |
|---|---|---|---|---|
| **热层** | 人设核心 + 行为规则 + 当前用户好感摘要 + MEMORY.md 进化结论 | 每轮，同步读盘（mtime 缓存） | ≤ 700 字，代码硬截断 | `core.js:4292 buildMessages()` 里加 `learn.hot(ctx)` |
| **温层** | 该用户的知识库、偏好档案、历史话题标签 | 命中回溯词/问事实时才检索 | ≤ 500 字 | `learn.warm(ctx, query)`，在 `localsearch` 的触发条件里挂钩 |
| **冷层** | 完整交互日志 + 输出证据链 | 审计/复盘/导出时 | 不进提示词 | `acts/YYYY-MM.jsonl`，append-only |

**「不每次当场重算」怎么保证**：
- 注入的永远是**已经写好的句子**（md/json 里的结论），不是让模型现场归纳；
- 学习发生在**聊天热路径之外**：`learnWorker` 空闲定时跑（默认 90 秒一次，可关），一轮聊天只多一次读盘；
- 一次学习的产物落盘后，下一轮直接读，模型不再重新判断。

  "firstSeenAt": "2026-10-02T11:00:00Z",
  "lastSeenAt": "2026-11-09T04:10:00Z"

### 4.2 `users/<pid>/favor.jsonl`（一行一个事件，只追加）
```json
{"id":"fv_20261109_0001","ts":"2026-11-09T04:12:00Z","pid":"p_6a3f","delta":3,
 "before":59,"after":62,"trigger":"event","reason":"她记住了他提过的生日",
 "evidence":{"ref":"data/chat-log.jsonl#L8821","quote":"我生日是三月七"},
 "by":"bot","rev":null}
```
- `trigger` 四选一：`event`（具体事）/ `chat`（聊天表现）/ `decay`（衰减）/ `manual`（她在客户端手改）
- **撤销** = 追加一条 `delta` 相反的记录，`rev.of` 指向原 id；**永不删原记录**（审计要留）
- `decay` 记录直接写负数 delta，理由固定为「N 天没说过话」

```markdown

- 2026-11-03 群 894917172：「别问我了」（evidence: chat-log#L7712）
```

## 5 关键机制

### 5.1 好感衰减（参数待她定，见 §7-D1）
- 默认：非主人 **7 天没说话才开始衰减**，每天 `-0.3`，不做成负数（下限 0）；
- 主人永不衰减；
- 衰减只写事件流水，**不直接改分数**——下次读的时候按流水重算，这样可回滚；
- 一次衰减事件连续 30 天不重复写（合并成一条），避免一天一行。

### 5.2 混合检索（她 2026-11-09 定：装 Ollama 换真向量）
- **关键词**：字符二元组（bigram）倒排索引 + BM25-lite，中文不用分词；
- **语义**：Ollama 本地嵌入模型出真向量，余弦相似度；
- **融合**：两路各出前 N 名，按 **RRF（reciprocal rank fusion，倒数名次融合）** 合并——只用名次不用分数，
  因为 BM25 分数和向量距离量纲不同，直接加权会互相压死（NexusMem 踩过这个坑）；
- 低于阈值返回空（**不硬凑**），最多 3 条；
- **Ollama 没起来时自动退化**：只用关键词那一路，不报错、不阻塞回答问题；
- 留 `embed()` 单函数，换模型只改它。

> 本机现状（2026-11-09 实测）：`which ollama` 无输出，`127.0.0.1:11434` 拒绝连接 → **还没装**。
> 装它需要下载安装包 + 一个嵌入模型（几百 MB 到 1 GB），且要常驻后台。这一步单独做，不塞进 P0。

### 5.3 受控进化（防人格漂移）
```
每轮输出 → acts 冷层
   ↓（定时 worker）
短期信念 beliefs.json：同方向 +1，反向 -1，conf<0.3 删除，过期自动清
   ↓（反射阈值：同方向 ≥3 次且跨 ≥3 天）
候选长期特质 → 四项校验
   ① 不撞 identity.md / 铁律（逐条比对，撞了直接拒）
   ② 不动「原则/协议」段
   ③ diff 幅度 ≤ 阈值（默认删改 ≤ 2 句/次）
   ④ 有证据（至少 3 条 acts 引用）
   ↓ 通过
versions/<ts>.json 快照 → 写 traits.json → 写回 data/记忆/长期.md 的「每轮给模型看的」段
   ↓ 不通过
记 ai-feedback「拒绝进化」，客户端可见，不静默
```
**为什么写回 `长期.md` 而不是新建 MEMORY.md**：`长期.md` 的「## 每轮给模型看的」段已经是每轮注入点，
再建一份 `MEMORY.md` 就是两个热层文件、两套优先级，必然打架。要独立名字我再拆（见 §7-D2）。

### 5.4 顺序与优先级（写死，不许模型自己排）
1. 人设正文（`soul/`）
2. 固定规则（`systemPrompt()`）
3. **每人风格三份（新）** ← 她要的「优先级高于普通记忆」
4. 好感摘要（新）
5. MEMORY.md 进化结论（复用 `长期.md`）
6. 普通记忆 / 温层检索结果

`learn.hot()` 只负责 3、4，第 5 走原 `memory.longForPrompt()`，位置就在它前面。

### 9.4 机器人怎么用上（`src/learn/bridge.js`）

插件跑在 DSH 里，机器人是另一个进程。两者靠**档案文件**接上，不靠共享进程：

| 档案 | 路径 | 谁写 | 谁读 |
|---|---|---|---|
| 风格画像卡 | `~/.dsh/style-memory/profile.json` | `dsh-style-memory` | `bridge.js`（只读） |
| 写作风格档案 | `~/.dsh/Writing-Style/profiles.json` | `dsh-writing-style-learner` | `bridge.js`（只读） |

- 卡片渲染**优先调插件自己的 `lib/card.js`**（动态 `import()`，这个文件不依赖宿主 ctx）。找不到才用本地兜底渲染——这样插件升级了卡片风格，机器人跟着变，不会两套逻辑打架；
- `hot()` 是同步的，所以读盘放在 `refresh()`：机器人启动 20 秒后一次、之后跟 `learn.tick()` 每 30 分钟一次，结果存内存；
- 注入位置：**每人风格三份 → DSH 风格档案 → 好感摘要**。先定「怎么说」，再说「对谁什么态度」；
- 上限 700 字（`features.learn.dshChars`），关掉 `features.learn.dsh` 就整段消失；
- 读不到、格式变了、插件卸了——一律返回空字符串，不抛错、不影响回话。
