## 1. 系统 DNS 坏掉时的自救：自定义解析 + IP 直连

**场景**：`fetch` 报 `fetch failed` / `getaddrinfo ENOTFOUND`，但 `nslookup` 正常、TCP 能通。多见于代理软件劫持 DNS、Windows DNS Client 服务异常。

**出处**：`core.js` 的 `resolveHost()` + `postJson()`

```js
const https = require('https');
const http = require('http');
const dns = require('dns');
const ipCache = new Map();          // host -> { ip, at }

function resolveHost(host) {
  const hit = ipCache.get(host);
  if (hit && Date.now() - hit.at < 300000) return Promise.resolve(hit.ip);
  const save = ip => { ipCache.set(host, { ip, at: Date.now() }); return ip; };
  return new Promise(res => {
    dns.lookup(host, { family: 4 }, (e, a) => {
      if (!e && a) return res(save(a));
      const r = new dns.Resolver();                    // 系统解析失败 → 直接问公共 DNS
      r.setServers(['223.5.5.5', '119.29.29.29', '114.114.114.114']);
      r.resolve4(host, (e2, list) => {
        if (e2 || !list || !list.length) return res('');
        res(save(list[0]));
      });
    });
  });
}

function postJson(url, headers, bodyStr, timeoutMs) {
  return new Promise(async (resolve, reject) => {
    const u = new URL(url);
    const isHttps = u.protocol === 'https:';
    const host = u.hostname;
    const ip = await resolveHost(host);
    if (!ip) return reject(Object.assign(new Error('DNS 解析失败 ' + host), { code: 'ENOTFOUND' }));
    const mod = isHttps ? https : http;
    const req = mod.request({
      host: ip,                                   // 关键：连 IP
      port: u.port || (isHttps ? 443 : 80),
      path: u.pathname + u.search,
      method: 'POST',
      servername: isHttps ? host : undefined,     // 关键：SNI 用域名，证书校验照常
      headers: Object.assign({ Host: host, 'Content-Length': Buffer.byteLength(bodyStr) }, headers),
      timeout: timeoutMs || 30000,
    }, res => {
      let data = '';
      res.setEncoding('utf8');
      res.on('data', c => { data += c; });
      res.on('end', () => resolve({ status: res.statusCode, text: data }));
    });
    req.on('timeout', () => req.destroy(Object.assign(new Error('超时'), { code: 'ETIMEDOUT' })));
    req.on('error', e => reject(e));
    req.write(bodyStr);
    req.end();
  });
}
```

**要点**

- `servername` 一定要填域名，否则证书校验不过；填了之后 `rejectUnauthorized` 保持默认 `true` 就能通过
- 诊断顺序：`nslookup`（DNS 服务器好不好）→ `dns.lookup`（getaddrinfo 好不好）→ `/dev/tcp` 连 IP（TCP 通不通）→ `https.request` 直连 IP（TLS 通不通）。四步定位到具体哪一层
- 用 `fetch` 做不了这件事，因为 Node 的 fetch 不接受自定义 `lookup`

## 2. Markdown ↔ 无限层级树

**场景**：把 `#` 数量当层级，支持任意深（不止 6 级），还要能原样写回。

**出处**：`panel.js` 的 `parseMd / toMd`

```js
function parseMd(md) {
  const root = { level: 0, title: '', items: [], children: [] };
  const stack = [root];
  for (const line of String(md || '').split(/\r?\n/)) {
    const h = line.match(/^(#{1,12})\s+(.*)$/);
    if (h) {
      const lv = h[1].length;
      while (stack.length > 1 && stack[stack.length - 1].level >= lv) stack.pop();
      const node = { level: lv, title: h[2].trim() || '未命名', items: [], children: [] };
      stack[stack.length - 1].children.push(node);
      stack.push(node);
      continue;
    }
    // 其余行归到当前节点：- 列表 / > 引用 / 普通段落
    const cur = stack[stack.length - 1];
    const li = line.match(/^(\s*)[-*]\s+(.*)$/);
    const bq = line.match(/^\s*>\s?(.*)$/);
    if (li) { if (li[2].trim()) cur.items.push({ t: 'li', text: li[2].trim(), ind: li[1].length }); }
    else if (bq) { if (bq[1].trim()) cur.items.push({ t: 'p', text: '> ' + bq[1].trim() }); }
    else if (line.trim()) cur.items.push({ t: 'p', text: line.trim() });
  }
  return root;
}

function toMd(tree) {
  const out = [];
  const walk = (n, depth) => {
    out.push('#'.repeat(Math.max(1, Math.min(12, depth))) + ' ' + n.title);
    if (n.items.length) {
      out.push('');
      for (const i of n.items) {
        if (i.t === 'p') out.push('> ' + i.text.replace(/^>\s?/, ''));
        else out.push(' '.repeat(i.ind || 0) + '- ' + i.text);
      }
    }
    out.push('');
    for (const c of n.children) walk(c, depth + 1);
  };
  for (const c of tree.children) walk(c, 1);
  return out.join('\n').replace(/\n{3,}/g, '\n\n').trim() + '\n';
}
```

**要点**

- level 用 `depth` 重新算，别信任存下来的 level，删层级时才不会错位
- 往返测试：`JSON.stringify(parseMd(toMd(parseMd(md))))` 必须相同

## 3. LLM 调用：多模型链 + 冷却 + 错误分类

**场景**：免费模型经常 429/1305，需要自动切备用；主模型空闲时要能自动切回，且不能为了探测额外花钱。

**出处**：`core.js` 的 `askOnce / callLLM`

```js
let primaryCoolUntil = 0, primaryFailStreak = 0;

async function callLLM(messages) {
  const all = [llm.model, ...(llm.fallbackModels || [])].filter(Boolean);
  const primary = llm.model;
  const cooling = Date.now() < primaryCoolUntil;
  const models = cooling ? all.filter(m => m !== primary) : all;   // 冷却期直接跳过主模型
  let allBusy = true, allAuth = true, lastErr;
  for (const m of models) {
    try {
      const ans = await askOnce(m, messages);
      if (ans) {
        if (m === primary) { primaryFailStreak = 0; primaryCoolUntil = 0; }  // 主模型回来了
        return ans;
      }
    } catch (e) {
      lastErr = e;
      if (!e.busy) allBusy = false;
      if (!e.auth) allAuth = false;
      if (m === primary && e.busy) {          // 指数退避 30s → 60s → … 最多 5 分钟
        primaryFailStreak++;
        primaryCoolUntil = Date.now() + Math.min(300000, 30000 * Math.pow(2, primaryFailStreak - 1));
      }
    }
  }
  if (allAuth) throw new Error('AUTH');
  throw new Error(allBusy ? 'BUSY' : (lastErr ? lastErr.message : 'LLM 全失败'));
}
```

**要点**

- **不要发独立的"探测请求"**。冷却到期后，下一次真实对话自然就会先试主模型，成功即用它的回答，不产生额外 token
- 401/403 判 `auth`，429/5xx/1305 判 `busy`，网络错误判 `net` —— 三类要给用户三套话术，不能都回「脑子卡了一下」
- 网络错误自动重试 2 次（700ms / 1400ms 退避）能吃掉大部分抖动

## 4. 中文轻量检索：二字切片 + 覆盖度

**场景**：本地资料库没有向量库，也要判断「这个问题本地资料够不够答」。

**出处**：`guides.js`

```js
function grams(text) {
  const set = new Set();
  const low = String(text).toLowerCase();
  for (const w of low.match(/[a-z0-9]+/g) || []) if (w.length >= 2) set.add(w);
  const cj = low.replace(/[^\u4e00-\u9fa5]/g, '');
  for (let i = 0; i < cj.length - 1; i++) set.add(cj.slice(i, i + 2));
  return set;
}

// 覆盖度 = 问题切片中被资料命中的比例
function coverage(query, text) {
  const q = grams(query), t = grams(text);
  if (!q.size) return 1;
  let hit = 0;
  for (const x of q) if (t.has(x)) hit++;
  return hit / q.size;
}
```

**要点**

- 阈值 0.55 是好用的经验值：低于它说明资料缺得比较多
- **占位段要排除**（正文 < 120 字且含「待补/待填/TODO」），否则标题里的词会把覆盖率抬高，导致明明没资料却不联网
- 命中标题时直接信本地，不再联网（避免搜出二手错数值）

```js
function hlNodes(text, kw) {
  if (!kw) return [document.createTextNode(text)];
  const out = [], low = text.toLowerCase(), k = kw.toLowerCase();
  let i = 0;
  while (i < text.length) {
```

## 7. 踩坑清单（按代价排序）

1. **页面白屏**：把 JS 塞进服务端的模板字符串，正则里的 `\/` 被吃掉 → `SyntaxError`，整段不执行。**前端必须独立成文件**。
2. **`window.onerror` 抓不到 promise 里的错**：页面看着正常但没数据。要用 CDP 的 `Runtime.exceptionThrown` 看 `description`。
3. **DOM 桩测试会骗人**：它会自动创建缺失元素，正则炸了照样跑通。**交互类改动必须用真浏览器（CDP）验**。
4. **`_snap` 自引用**：快照字段挂在被序列化的对象上，脏判定永远为真。
5. **NapCat 配置按 QQ 号命名**：换号后新号是空配置（`websocketServers: []`），3001 不会开。要手动复制旧号那段。
6. **火绒会整个删掉 NapCat 目录**：必须把 `NapCat.Shell.Windows.OneKey` 加信任区。
7. **`toISOString()` 是 UTC**：北京时间晚 8 小时，晚上 8 点后日期会写成昨天。要用本地日期。
8. **`curl` 发中文 URL 会静默失败**：前端用 `encodeURIComponent`，服务端 `decodeURIComponent`。
9. **系统 DNS 坏掉时 `fetch` 全废**：见第 1 节，自定义解析 + IP 直连。
10. **跨目录拖拽文件必然错位**：显示顺序和磁盘目录不一致时会读错文件，只能在同目录内排序。
11. **把全局元素塞进会被隐藏的容器，会被连带藏掉**（2026-10-22）：状态栏原本写在 `.composer` 里，  
    而功能页（`__chat / __map / __log / __topic / __who / __raw_* / __table_*`）会把整个 `.composer`  
    `display:none`——结果主人切到任何功能页都看不到状态栏。  
    **全局元素必须挂在 `<main>` 直属层级**，功能页只隐藏它自己的输入区。  
    验证方式：Playwright 里 `getComputedStyle` 查该元素的 `display` 和 `getBoundingClientRect()`，  
    光查「元素存在」是查不出来的（元素在，只是看不见）。
12. **图片「看不见」往往不是模型坏了，是时机不对**（2026-10-22）：  
    原先只有机器人**决定回话**时（`handleTurn`）才去下载+识别，不回话就没翻译；  
    而且翻译结果只用于回话，聊天记录里永远是干秃秃的 `[图片]`。  
    **正确顺序：消息一进来就翻译，再写记录**（`onMessage` 最前面调用 `describeImgs`，  
    用 `［图：描述］` 占位符替换 `[图片]`，handleTurn 用 `takeImgDescs` 摘回来，不重复识别）。  
    诊断时先留证据：`console.log` 打 NapCat 给的是 `url` 还是只有 `file`；  
    只有 `file` 时用 OneBot `get_image` 换真实地址；图床防盗链加 `Referer: https://qzone.qq.com/`。

## 智谱接口：三个踩到的坑（2026-10-22 实测）

### 1. 403 + code 1220「IP 地址没有接口访问权限」＝ 后台开了 IP 白名单

不是代理、不是 Key、不是进程。判断依据：**同一把 Key 调 `/models` 正常返回，但一调生成接口就 403**。

- **要填的是公网出口 IP，不是 127.0.0.1**（回环地址，请求根本不从这里出去）。
- 查 IP 的可靠通道（`myip.ipip.net` 在这台机器上 SSL 握手失败）：
  ```
  curl -s --noproxy '*' https://ip.3322.net          # 返回 223.167.187.237 这种
  curl -s --noproxy '*' http://members.3322.org/dyndns/getip
  ```
- **家用宽带重启光猫/路由器 IP 会变**，变了这个错会原样重现。觉得麻烦就把白名单清空（多数情况＝不限制）。
- 用一把假 Key 能区分两种封禁：假 Key 也报 1220 → 是 **IP 级**；假 Key 报 401、真 Key 报 1220 → 是**账号级**。

### 2. 思考型模型会把 max_tokens 烧在「思路」上，正文变空

`GLM-4.7-Flash` 的返回里正文在 `choices[0].message.content`，思路在 `reasoning_content`。  
`max_tokens: 600` 时它先写思路，额度写完正文还没开始 → `content: ""` → 上层判「全是空内容」→ 白等一轮再降级。

实测同一句话：开思考，思路烧了 1158 字正文还是空；关掉思考，立刻出正文、更快更省。

```js
// 按模型名单开关，别一刀切——不认这个参数的旧模型会报错
const noThink = Array.isArray(llm.noThinkModels) && llm.noThinkModels.indexOf(model) >= 0;
const body = { model, messages, temperature: 0.9, max_tokens: 600 };
if (noThink) body.thinking = { type: 'disabled' };
```

### 3. 400 + code 1214「messages 参数非法」

多半是**发过去的 messages 里一条 user 消息都没有**（全是 system）。  
正常流程不会犯（会话进来先 `pushHist` 再 chat），**自己写脚本测的时候最容易漏**。  
另外 `buildMessages` 是 async，直接 `core.buildMessages(...)` 拿到的是 Promise，忘了 await 就会把 Promise 塞进 JSON。

## 「等说话的人把话一次性说完」的通用写法（debounce）

需求：对方习惯一句一句发，不许逐条回，静默 N 秒算他说完了。

```js
const pendingTalk = new Map();   // key -> { pieces:[], firstAt, timer }
function push(key, piece, waitMs) {
  let p = pendingTalk.get(key);
  if (!p) p = { pieces: [], firstAt: Date.now(), timer: null };
  p.pieces.push(piece);
  if (p.timer) clearTimeout(p.timer);
  // 关键：三条上限防止「他一直在说」导致永远不触发
  const left = Math.min(waitMs, Math.max(0, maxMs - (Date.now() - p.firstAt)));
  const tooMuch = p.pieces.length >= maxPieces || chars(p.pieces) >= maxChars;
  p.timer = setTimeout(() => flush(key), tooMuch ? 0 : left);
}
```

三个要点：

1. **key 要带上说话的人**（`会话#uid`），否则群里两个人轮流说话会互相顶掉彼此的等待。
2. **一定要有「攒够了就发」的兜底**（条数 / 字数 / 总时长），不然对方一直不停地说就永远等不到回复。
3. **判定在发出的那一刻按合并后的整段走**，不要在第一条进来时就判定——否则「第一句不像提问、第二句才是」就漏了。

另外两类消息**不该参与等待**：低风险的即时指令（骰子这种）和**带资源的消息**（图片链接会过期）。

## 喜好三态：确定 > 可能 > 待确认（2026-10-22，主人定）

需求原话：「口味可以中立，因为喜恶里没有的就是中立，但是需要记录成待确认让我选，没确认的依旧中立。以及不确定的算比较中立，但是有偏好」。

做法：同一个东西在文件里只有一个位置，靠**优先级升降级**维护，不靠人工搬：

```js
const PRIO = { likeConf: 3, hateConf: 3, likeGuess: 2, hateGuess: 2, pending: 1 };
// 写入前先找同内容旧行：旧的更硬 → 不动；旧的更软 → 删旧行写新的；
// 同为「确定」但极性相反（喜欢 vs 讨厌）→ 后说的赢。
```

三个可复用的判断：

1. **「确定」只认原话**，不认模型自评——免费模型会把「猫比狗可爱」判成「确定讨厌狗」。用 `saidIn(原话, 词)` 反查。
2. **「待确认」是给主人看的待办，不是机器人的态度**。注入 prompt 时它单独一行「还没表态的（中立，别说喜欢也别说讨厌）」，主人在面板里把它拖到「确定」才算数——面板本来就是通用 md 编辑，不需要为它写按钮。
3. **模型整理时多要一个 `mention` 数组**（提过但没表态的具体东西），这是「待确认」的唯一来源；prompt 里必须写「宁可少放、别乱放」，否则会把天气都记成待确认。

## 「点话」类需求：意图正则必须先对上用户的原话句式（2026-10-22）

踩到的坑：主人说「希望你下次可以说X」，机器人回「好，知道啦」，但**磁盘上什么都没有**。  
根因：记忆意图正则只认「记到 / 记住 / 小本本」这套词，「希望你说」一个都不匹配，  
于是这句话掉到模型那里，模型嘴上答应、没有任何写盘动作——看起来就像「机器人从来不写东西」。

教训：**用户每发明一种新的吩咐句式，就要有一种新的落盘通道**，而且它要排在模型前面：

```js
const WISH_RE = /(希望你(?:下次|以后|之后|待会)?(?:可以|能|要)?说|想让你说|想听你说)/;
// 取出要记的内容：优先引号里，没有引号就取到标点为止；太短（<2 字）不要
```

配套两条：

1. **回执就按她要求的说**，别自由发挥——她说回「好，知道啦」就回「好，知道啦」，写去哪一栏靠面板红点和文件结构告诉她，不靠话多。
2. **预建目标小节**（`### 想听我说`）：空的也建，主人在面板里一眼看得见话都去哪了，机器人每轮也读得到（MEMORY.md 整份注入）。

## 管理面板：一份 FILE_META 管好「所有文件 + 只读 + 悬停说明」（2026-10-22）

需求原话：「所有用到的文件都放进来，我碰了会有问题的让我不能编辑，可以改的数据可以动，并且悬停告诉我什么用，区间范围代表什么」。

做法：`panel.js` 里一张 `FILE_META` 表把每个文件登记 `{cat, ro, kind, use, range}`，`buildNav()` 据此生成 7 类导航树：

- 代码（.js）`ro=true` 恒只读；`config.json` 可编辑，但 `POST /api/raw` 保存前 `JSON.parse` 校验，坏 JSON 直接拒（不落盘）——既让主人能调参，又不会手滑改坏结构。
- 原文查看 / 编辑走 `/api/raw`，`rawOk` 用 `p===ROOT || p.startsWith(ROOT+path.sep)` + 扩展名白名单防目录穿越。
- 悬停说明 = `use + range`；`range` 专给可调参数写合理区间（`chime.p` 0.02~0.3 等）。

可复用点：拖拽换分类写 `config.panel.catOverride`，`buildNav` 里 `catOf` 先查 override 再查 FILE_META；未登记的新文件自动落「其他」，不会消失。

坑：**draggable 行必须 `e.dataTransfer.setData('text/plain', id)` + `effectAllowed='move'`**，否则浏览器把拖拽当默认行为处理（用户反馈「我的拖动怎么变成搜索了」）。

## 面板「点了没反应」类 bug 的排查法（2026-10-22，真事）

主人报「保存没反应了，因为你在思考吗？bug？」。逐层查下来是三个互不相关的真因，记一下排查顺序：

1. **先看 `window.onerror` 红条/控制台**——本项目 `panel.html` 顶部有 `#errbox`，任何未捕获异常都会显示。本次真因之一就是渲染函数抛错，把后面的逻辑（自动保存调度）整段跳过。**异常在事件回调里会静默跳过后续语句**，表现就是「点了没反应」。
2. **再问「这个按钮的 handler 依赖的函数还在吗」**——重构删了 `inGroup/moveToGroup`，旧 `moveFile` 还在调；因为 `GROUPS` 退化成空数组，`[].find` 不抛错，成了**无声空操作**。比抛错更难发现。
3. **再看用户的操作路径和键盘习惯**——composer 只认 Ctrl+回车，主人按回车（QQ 习惯）自然觉得坏了。

可复用防御：

- 渲染函数要么返回节点、要么只 append，**别又 append 又 return undefined 给上层 appendChild**；
- 所有 POST 都 `.catch`/try-catch，**失败必须 toast**，不许静默；
- 保存类操作加**防抖自动保存**（停顿 1.5s 落盘），从根上消灭「忘了点保存」；
- 关键交互配一个无头浏览器脚本回归（Playwright + 系统 Chrome `channel:'chrome'`，不用下载浏览器）。

## 同名函数被旧定义覆盖（2026-10-22 真事，最难发现的一类）

`panel-client.js` 重构时新写了 `moveFile`（基于导航树），但旧的 `moveFile/groupOf` 代码块没删——**JS 里后面的 function 声明覆盖前面的**，且旧实现引用已不存在的 `inGroup`，`GROUPS` 退化成空数组所以 `[].find` 不抛错，拖文件成了无声空操作。

防御：重构删除函数后，全局搜一遍函数名确认只有一处定义；`grep -n "function xxx" file` 数出现次数，比读代码可靠。

## 话题连续性：没人 @ 也要接话的判据（可移植到任何「插话」场景）

`connectors/qq.js → recentTalk/topicAllowed`：每会话维护一个环形缓冲（用户消息 + 机器人自己的回复都进，窗口 90 秒）。判据 = 她刚参与过这段对话（缓冲里有她的消息）→ 她说完没人接则话题断了 → 之后有人接话才轮到；和最近几句有**二字切片重合**一定接，短句没重合按概率接（0.4）。

可复用点：中文重合度用**二字切片集合求交**（`sliceSet/sliceShared`，和 guides.js 一个思路），比关键词匹配抗同义词。回复要过质检（一句话、≤45 字、结尾不许问号、不许「你们/大家」旁观口气），不合格重说一次，两次不行这句不说——**沉默比硬接好**。

## 秒回的判定：引用回复 = 等同 @（OneBot 11）

对方「引用回复」机器人的消息时，`parseSegments` 拿不到 at 标识，要 `callApi('get_msg', {message_id: replyId})` 反查原消息的 `sender.user_id` 是不是自己——是则按 atMe 处理（`waitMs=0` 立即回）。超时 2.5 秒拿不到就按普通消息走，不阻塞。

## 面板后端调 LLM（面板按钮触发模型总结）

`panel.js → llmSay(prompt)`：读 `config.llm` 的 endpoint/apiKey，按 `[model, ...fallbackModels]` 链依次试，`AbortController` 45 秒超时。面板自己的按钮（话题「让它总结」）和机器人共用同一条模型链，Key 只用一处。

## LLM 复读的根因往往在「历史格式」，不在模型（2026-10-22 真事）

机器人原样复读了另一个机器人群友的欢迎语，连「WuuaBot说:」前缀一起抄。根因不是模型爱复读，是 `pushHist(k,'user', who+'说: '+content)` 把**机器人群友的消息也写进了会话历史**，且历史行自带「名字说:」前缀——模型把历史当前文格式模仿了。修法：接入层就要把「不是人的消息」挡在历史之外（只 logLine），比在 prompt 里写「别复读」可靠一个数量级。

## 「提问自动接」的关键词表一定要配负面豁免（2026-10-22 真事）

`AUTO_ASK_DEFAULT` 里有裸「怎么」，导致「怎么感觉有点蠢」被当成提问去联网搜（bot-out.log 有搜索记录），还答错了腔。凡「怎么/如何」开头 + 感觉/觉得 + 负面形容词的，是抱怨不是提问。通用教训：关键词表只管「像什么」，负面清单管「不像什么」，两个都要有。

## 双进程事故：Stop-Process 整条命令被拦时，后面的启动不会执行

重启 bot/面板时 PowerShell 复合命令（Stop + Start-Process）被安全策略整条拦下，旧进程没杀、新进程也没起；随后用 Bash 后台起了新进程，变成**两个 bot 同时连 NapCat**（双回复风险）。教训：① 杀进程和起进程分成独立调用、各自确认；② 起完必须列进程，确认 PID 数和 CommandLine 符合预期（一旧一新两个 bot.js 就是靠这个发现的）。

## 面板写入口必须检查写盘返回值 + 写后读回（2026-11-22 真事）

**症状**：她在面板的人物卡里改「真名 / 所在地」，界面回「已保存」，重开又变回去。

**根因**：`/api/people/set` 调完 `writePeopleState(st)` 不看返回值，无条件 `return json({ok:true})`；而 `people.writeStateView` 默认 `allowIdentity:'sync'`，save 的人名硬闸只许「补空」，**改已有名字必被拒**。于是文件一字未动、接口说 ok，界面毫无报错——典型静默失败。

**改法（三件事，缺一不可）**
1. 写盘函数要能给出人话原因：`people.lastWriteError()` / `saveEx()`；接口按真实结果回 `{error}`，不再无条件 ok。
2. 面板手动改走 `allowIdentity:'user'`（`writeStateView(st,{mode:'user'})`），脚本 / 模型路径仍是 `sync` / `qqsync`，人名闸不被放宽。
3. 客户端保存后**读回校验**：写完 `GET /api/friends` 比对每个字段，不一致红字点名「哪一项没落地」，全对才说「已保存」。

**顺手挖出的两个坑**
- 老接口按 QQ 写称呼时，没建档的号会被 `writeStateView` 里 `makePerson` **凭空造一个人**；写错一个号人物表就多一条。写入口先 `findByAccount` 挡掉。
- `tests/test-all.js` 起 8799 面板固定 `setTimeout(1500)`，外置卷冷启动要 2~3 秒 → 假失败。改成 300ms 轮询、最多等 12 秒。

**回归测试**：`tests/test-person-save.js`（npm test 末尾跑）。把 people/region/wlog 和一份数据复制到临时目录跑，不碰真实 `src/data`；守住「面板档能改、同步档被拒且给原因、陌生号不造人、地区读写一致、同秒连写不丢」。
