## 版头

### 1. 项目含义

不是问答机器人，是「有性格、记事情、会主动接话」的存在。

- 人设：小笨蛋、会脸红、被夸会开心；短句、口语化、不用「嘿嘿」只用「嘻嘻」。
- 记忆：记得谁喜欢什么、谁在哪、谁被夸过，能按分类自己归档。
- 分身：她说过「机器人是她在网络上的分身」，说话味道学她，但不许冒充她本人。
- 攻略库：本地 md 检索（速速上菜 / 洛克王国 / 渔力全开），答攻略只给数值不加语气。
- 面板：浏览器里改人设、记忆、口味、攻略、称呼、表情包，看聊天记录和花费账。

### 2. 功能总览（一句话一个）

- 群里聊天：被 @、被引用、被问、被吐槽、纯随机搭话，共八条路径决定她什么时候开口。
- 等你说完再答：你一句句发，她攒够静默才答一次，不逐条插嘴。
- 学你说话：只收你在群里自然打的字，定时总结成风格，注入时随机抽 4 条。
- 记口味：喜欢/讨厌 × 确定/可能/待确认 五栏，她的口味就是你的口味。
- 单人约定：群友让她「以后句尾加个 Ciallo」，只对那个人生效。
- 梗：命中梗库按库接，认得出结构就照构式造，都不行才短吐槽兜底，不许编出处。
- 笑点解析：五步链路拆分层笑点，格式照你手写的范例。
- 骰子：接了 SealDice 官方引擎，11 个命令，TRPG 全套记号。
- 表情包：五个池 + 三处触发（情绪场合表 / 关键词触发文件夹 / 纯情绪），32 行一族，说一半说错了也能发。根目录只认 q 情绪图，关键词图全在 关键词触发/。
- QQ 空间：每 3 小时逛一次真空间，转发、发自己的说说，都私聊告诉你。
- 收图：你发的进可用池，别人发的和 B 站评论区的进普通池，内容重复不收。
- 暂停/允许：私聊一句话让某个群或某个人静音，到点自动恢复。
- 自检：每 5 分钟自己体检，出问题私信你；另有手动深度巡检和代码自检。
- 面板：五类文件夹 + 触发地图 + 聊天记录 + 话题日志 + 规矩手册 + 花费账 + 她的思考。
- 更新弹窗：每次改完代码必须写一条说明，你点「知道了」才算看过。

### 3. 风险（会真出事的地方）

- 只读看配置不许调 core.init({})：它会「缺项就写盘」，传空对象能把 config.json 从 3.8KB 覆盖成 416 字节骨架（2026-11-01 真出过）。要动先 cp 一份、跑完比 sha256。
- 双开：两个 bot 抢同一个 ws 端口，一条消息回两遍。启动.command 已加 pid 探活拦截，但别手动再起一个。
- 面板旧进程跑旧代码：改了 panel.js 不重启面板，界面上还是老逻辑，会让人以为改坏了。
- 上游 429 限流：免费模型排队时整段落速，备用链会切到最弱模型，话会变笨。
- 思考型模型烧空正文：GLM-4.7-Flash 先写 reasoning_content，max_tokens 给小了正文就是空的，已在 noThinkModels 关掉思考。
- 举例句进提示词会被照抄：免费模型会一字不差抄范例。梗库只给「怎么接」的方向，例句只用于校验。
- 面板不渲染表格和加粗：写给她看的 md 一律用「- 名字：说明」条目。
- 机器人主动加群做不到：NapCat 没有这个动作（retcode 1404）。说了「已成功加入」就是谎报，发送层已拦。

## 一、给主人看的

### 1. 现在有的功能

- 聊天接话：被 @、被引用、群里有人问问题、有人吐槽、纯随机搭话 —— 五种都会接
- 等你说完：你一句句发，她等你停下才答，不会一句一答
- 学你说话：只学你在群里自然说的话（@ 她和私聊的不学）
- 记口味：喜欢 / 讨厌 / 待确认分开记，她的口味就是你的口味
- 记约定：谁跟她说「以后句尾加个喵」，只对那一个人生效
- 梗与笑点解析：说「笑点解析」她就按你写的范例分层拆
- 骰子：.r 投骰、.rc 检定、.sc 理智、.ww / .dx / .rb 等全套
- 表情包：32 行一族，纯情绪甩图，关键词在 关键词触发/ 里说一半或说错了也能发
- QQ 空间：逛真空间、转发、发自己的说说，都私聊告诉你
- 收图：你发的进可用池，B 站的进普通池，重复的不收
- 暂停 / 允许：私聊说「暂停群XXXX」，那个群她就闭嘴
- 自检：她自己每 5 分钟体检，有问题私信你
- 面板：改人设、记忆、口味、表情包，看聊天记录、话题日志、花费账
- 陪玩（2026-11-02）：Windows 那边每 15 秒发一张游戏画面过来，她看一眼说一句话，字幕和声音出现在 OBS 里；同时读你的 B站直播弹幕，观众发的话她挑着回——陪你打《影之刃零》用

### 2. 你从哪进

- 启动机器人：双击 xuhbot/xuhchatrule/xuhctrl/启动.command。窗口开着 = 在线，关掉 = 下线
- 查机器人群有没有留痕：双击 虚幻bot/检查不记录群.command（软链接，真身在 xuhbot/xuhchatrule/tools/）。输出里每一项都该是 0
- 重启 AstrBot 后端（改完 memshare 插件/配置之后用）：双击 虚幻bot/重启AstrBot后端.command（软链接，真身同上）。它等 6199 端口在监听才报成功，最多 80 秒
- 打开面板：双击 xuhuan mac/管理面板.command，浏览器开 127.0.0.1:8899
- 换 Key：双击 xuhbot/xuhctrl/setkey.js
- 表情包维护：双击 xuhuan mac/表情包维护.command
- 陪玩（直播/录像）：双击 xuhuan mac/陪玩启动.command。跑起来后自己看进度开 127.0.0.1:8900，OBS 的浏览器源填 192.168.124.24:8900/live（含字幕 + 右侧弹幕条）；再双击一次这个文件 = 问你要不要停。B站弹幕自动连你的直播间，房间号在 app/bili-config.json
- QQ 在线：由 NapCat 管（安装器在 xuhuan mac/NapCat安装器，AstrBot 在 xuhuan mac/astrbot）。机器人进程停了 QQ 还挂着，关掉 NapCat 才是真下线

### 3. 改一处会影响哪

- 改人设 soul/虚幻.md → 每句话都受影响，面板里能直接改，改完下一句就生效
- 改口味 data/人物喜好.md → 她说话的口径跟着变；面板里把「待确认」拖到「确定」就算你认下了
- 改表情场合表 data/stickers/常用.md → 自动重建 data/stickers/清单.md（模型看的提示词）→ 面板顶部「N 行 · M 字 · 覆盖 X 张」跟着变
- 往表情 四个池 丢新图 → 面板 ③ 出现它 → 自动补一句描述标黄 → 点「↺ 重制」才正式进 常用.md
- 改 config.json 里的数字（等待秒数、搭话频率）→ 立刻生效，不用重启；面板「规矩」页能直接改
- 改 core.js / connectors/qq.js / dice.js 等代码 → 必须重启机器人才生效
- 改 panel.js / panel-client.js / panel.html → 必须重启面板才生效，浏览器还要 Cmd+R
- 改 companion.js → 必须重启陪玩服务才生效（启动文件里选停、再双击一次）；QQ 群那边完全不受影响
- 改 persona/1-人设正文/说话风格.md → 陪玩时的语气跟着变，下次启动陪玩才生效
- 改 Mac 的局域网 IP（换 WiFi、换路由）→ 要同步改 Windows 上 companion-shot.ps1 第一行的 MacUrl，不然发不出来

### 4. 出问题怎么查

- 面板顶部状态灯：亮红的写什么就是什么（机器人进程退出、暂停中、自查有问题）
- 群里她不说话：先看是不是暂停了，再看是不是模型限流，最后才看 NapCat
- 双击 自检：跑 node selfcheck.js --deep，五类一次查完，人读报告在 data/自检报告.md
- 她说「我记住了」但其实没写：看面板「写入日志」页有没有那一条
- 陪玩不出声/不说话：Mac 浏览器开 127.0.0.1:8900，最上面「状态」那行会自己说卡在哪（还没收到画面 / 太频繁 / 看图报错）
- 陪玩连不上：Windows 浏览器打开 192.168.124.24:8900，能看到页面就说明网通，看不到就是 WiFi 不同或 Mac 服务没开

### 5. 别踩的坑

- 不要同时开两个启动窗口：会双开，一条消息回两遍
- 想重启用「一键重启」，不要自己再双击（虽然现在双击也不会双开，但多一步提示）
- 不要在面板里手改 清单.md：它是生成物，下次重建会被覆盖，要改就改 常用.md
- 不要把表情图丢进 常用/ 却不写场合：情绪类没写场合就永远发不出去
- 不要以为「窗口开着」就是在线：进程可能已经退了，看面板状态灯
- 陪玩截图全是黑的：游戏开的是「全屏独占」，Windows 截不到游戏画面。改成「无边框窗口」才行，设一次就好
- 8899 和 8900 是两个东西：8899 是面板（你自己看），8900 是陪玩（OBS 拉流），别填错
- 陪玩和机器人是两个进程：关掉陪玩，QQ 群里的她照样活着，两件事互不影响

## 二、给 AI 看的

### 1. 技术栈

- QQ 连接：NapCat（OneBot 11 正向 WebSocket，127.0.0.1:3001）
- 框架：AstrBot（xuhuan mac/astrbot）+ 本项目自己的 bot.js
- 模型：智谱 GLM-4.7-Flash；备用链 glm-4.5-flash / glm-4.5-air / glm-4-flash-250414
- 看图：glm-4v-flash，兜底 glm-4.1v-thinking-flash
- 联网：智谱 search_std；额度用完 429 时走 bingScrape 兜底（0 元）
- 运行时：Node 22（优先用 ~/.workbuddy/binaries/node/versions/*/bin/node）
- 面板：原生 Node http + 纯前端，无框架无构建

### 2. 目录与文件职责

- bot.js：入口。读配置、起 QQ 连接、定时日记、每 30 分钟话题自动总结
- core.js：大脑。提示词组装、LLM 调用（callLLM / askOnce / seeOnce）、记忆写入、口味、风格、清单生成、记账
- connectors/qq.js：OneBot 适配器。收消息、判决走哪条路径、挑图、发送、对账、收图
- panel.js：面板服务端。FILE_META 登记、/api/* 接口、规矩手册、花费账聚合
- panel-client.js：面板前端。树视图、文件页、表情页、聊天记录、话题日志
- panel.html：面板骨架 + 全部 CSS
- dice.js：骰子。SealDice 引擎 + 老 evalDice
- guides.js：攻略检索 + 梗库匹配
- nick.js：称呼状态机（酱 > 宝宝 > 昵称）+ 群名片
- taste.js：按人记喜恶（确定 / 可能 / 待确认）
- style.js：学她怎么说话
- region.js：地区识别
- favor.js：好感度
- pause.js：暂停 / 允许
- selfwatch.js：每 5 分钟自动体检
- selfcheck.js：手动自检（--deep / --why / --speed / --demo / --all / --restart）
- checks.js：检查引擎，自检和自动体检共用这一份
- websearch.js：联网搜索 + 链接理解 + 预热
- social.js：已随动态广场删除，不要再引用
- qzone_stroll.py：逛真 QQ 空间（转发、发说说）
- sticker_hash.py：算两张图像不像
- soul/虚幻.md：唯一的人设文件，机器不碰
- data/：全部数据（记忆、口味、风格、话题、聊天记录、表情、称呼、地区、状态、日志）
- docs/项目总览.md：指向总根真身的快捷方式
- integrations/、persona/：AstrBot 侧的接入与人设

### 3. 启动与运行

- 启动顺序：NapCat（QQ 在线）→ 启动.command（bot.js）→ 管理面板.command（可选）。面板和机器人是两个独立进程，改文件互不影响，但改代码各自要重启
- 启动.command 的行为：开头读 data/bot-status.json 的 pid，用 process.kill(pid,0) 探活，活着就提示 A bot is ALREADY running 并 8 秒后退出（防双开）；进程崩了同一窗口 5 秒后自动重启，连续退出 5 次改等 60 秒；等待用 ping 代替 timeout（timeout 在重定向环境里会直接失败）
- bot.js 兜底：uncaughtException / unhandledRejection 写 data/bot-err.log 后继续跑；SIGINT / SIGTERM 也记一笔（区分自己崩还是被关掉）
- 一键重启：selfcheck.js --restart 只重启 bot.js（不动面板、不动 NapCat），kill 完先等 8 秒复查有没有守护窗口接手，没人才自己 spawn，避免双开；顺手把 bot-status.json 的 thinking 复位
- 探活：setStatus() 写 pid；面板 /api/status 返回 pidAlive / botPid，灯红时提示「机器人进程已退出」
- 心跳：statusHeartbeat 每 60 秒刷一次 at，语义是「我活着」而不是「刚发生过事件」

### 4. 提示词怎么组装

- 注入顺序固定：人设 → 你认识的人 → 长期记忆 → 怎么读别人的话 → 环境 → 表情包 → 星标样本 → 说话风格 → 口味（core.systemPrompt）
- 人设只有一份 soul/虚幻.md。按「谁来写」分文件，不按内容分：soul 给人写、机器不碰；data/说话风格.md 给机器写，其中「## 主人自己补的」那节永远不覆盖、优先级最高。分法唯一的理由是读写隔离
- 人设写法：一条规则 = 一句要求 + 一个参考例子，格式「- 规则一句话。举例：「它该说的话」」，多个例子用顿号连；不用加粗；场景对照写「她说 X，我回 Y」并明确「场景对不上，一句都不许搬」
- 上下文闸：historyLimit 60 条 / historyChars 8000 字，pushHist 两道闸一起卡，只卡条数的话长文会把 prompt 撑到几万字
- 随机内容必须放末尾（starPrompt / style.block 每轮随机抽样本），前面稳定那段才能命中服务端 prefix cache。别把随机内容挪到人设前面
- readCached：soul 和 MEMORY 每轮都读，加 mtime 缓存，文件没改就直接用上次的字符串
- 本轮事实块：明确写「对方有没有 @ 你 / 有没有引用你 / 这句话在对谁说」，模型照抄不许脑补
- 能力清单也进提示词：能收拍一拍、能发图 / @ / 表情 / 搜索，做不到的（主动加群）明写做不到

### 5. 上下文怎么取（全项目统一口径）

- 定义：凡功能需要「具体聊天记录」当材料（解析谁、记什么、总结哪段），一律由代码从聊天流水里按固定口径截取原文喂给它，不让模型自己回忆
- 口径：群聊上 10 条、下 3 条；单人（只看触发者自己）上 5 条；以触发消息时间为界；机器人自己的消息不算；图片算一条（翻译已在文本里）
- 实现：qq.js instantLog(gkey, 60) 取群流水 → pre.slice(-10) / post.slice(0, 3) / 本人 slice(-5)
- 适用：笑点解析、话题总结、一键记梗、梗库与话题检索的现场材料
- 原理：原文优先（引用 > 图片 > 最近发言）→ 固定窗口（数量写死在代码里，不随 prompt 漂移）→ 边界明确（下 3 条等 6 秒，补刀也算材料）→ 短材料用二字切片匹配
- 局限：窗口外更早的梗史看不到；下文最多等 6 秒；上下文行截断到 300 字会丢细节；图片只有翻译文本

### 6. 什么时候说话

八条路径，全在 connectors/qq.js → onMessage，按顺序判断，命中一条就接：

- atMe：被 @，或对方引用回复她的消息 → 必回，最直接
- autoAsk：群里没 @ + 文本像提问 + 限流通过
- comment：主人或欧尼酱说「X 是这样的」这类锐评 + 限流通过
- banter：5 分钟内在这个群说过话 + 有人吐槽「你俩 / 这机器人 / 笑死」→ 只怼回去
- chime：群里正常聊天，按小概率随机搭一句（有每日上限和间隔）
- topic：话题连续性，她参与过的对话被接上时才接（第七条路径）
- 问候：打招呼 / 晚安类，群聊没 @ 也回
- 骰子：文本以 . 或 。开头 → 不走模型

各条参数（数字以 config.json 现读为准，别在这里另记一份）：

- autoAsk：长度 ≥ minLength（默认 5）；命中疑问词（怎样 / 怎么 / 如何 / 是什么 / 为什么 / 哪里 / 多少 / 是不是 / 能不能 / 有没有 / 吗 / 呢 / 问号）；每分钟最多 3 次、两次之间至少 12 秒。陈述句没有问号也没有疑问词，本来就不触发 —— 「以前会回现在不回」多数是这个原因，不是坏了
- comment：只认主人和欧尼酱；长度 4~80；不能带问号（带问号走 autoAsk）；命中「是这样的 / 就是这样 / 这德行 / 果然 / 早就说过 / 难怪 / 笑死 / 绷不住 / 典中典 / 逆天」；回复要求八个字以内、只说态度、不许出现他话里的名词，复述或撒娇判不合格重说一次，再不行用附和池
- chime：只在群里、没 @ 她、前面几条都没命中时才轮到；minLength 默认 4；两条之间至少 cooldownMs（3 分钟）；每群每天最多 dailyMax（80 句）；平时概率 p 默认 0.11；到 warmupHour（20 点）还没说够 warmupMin（30 句）概率临时提到 warmupP（0.16）；说出来的话要过 chimeOk：一句话、≤45 字、结尾不许问号、不许「你们 / 大家 / 请问 / 建议你 / 我是AI」，不合格重说一次，再不行这句直接不说。口径来自她「500 条 / 天 → 30~80 句」
- topic：recentTalk 环形缓冲每会话最近 40 条，窗口 90 秒；minGapMs 20 秒内不连说；和最近几句有二字重合按 hitP（0.6）概率接，没重合按 p（0.25）；dailyMax 60 句 / 天；回复同样过 topicOk
- 被 @ 热状态：被 @ 一次（含引用）后阈值临时降到 grpAuto.hotMin~hotMax（4~10 条就能自主搭话），持续 hotMsMin~hotMsMax（0.3~2 分钟，每次随机）。和 chime 的概率 / 冷却 / 日上限互相独立
- 复读链：群里同一句话被连续发 ≥2 次（3~5 分钟窗、最近一条 150 秒内、不算她自己、不算 peerAI）→ 原样跟一条；每条链最多跟一次；带 @ / 带图 / 指令式不跟；超长（>60 字）按一半概率
- 主人必回：主人的两个号在群里发言不走群级节流、不走凑热闹概率、不看「不用回复」名单，等合并后必答；必回不算自主发言，不消耗群节流；必回触发时不 @ 主人（被 @ 触发才 @）
- 暂停 / 允许：私聊「暂停群894917172」「暂停欧尼酱 2小时」「暂停列表」「允许xx」；闸在记完聊天记录之后、复读链之前；主人只豁免私聊，在被暂停的群里主人也闭嘴；命令本身在闸前面处理，所以群里也解得开
- 不记录群：config/features.json 的 noRecordGroups（群号数组，如 [143620228]）里的群「只接话、不落盘」——聊天记录 / 记忆 / 话题 / 口味 / 风格 / 认人 / 约定 / 地区 / 纠正 / 首见全不写；内存里的本会话上下文照常留着（回复照样有上下文、不崩），但重启即清空、不污染任何数据文件。改这个数组即时生效不用重启；代码层拦截在 core.js 的 isNoRecordScope（core.logLine 和 core.topicAdd 共用同一个判断）+ qq.js 各写盘调用前。2026-11-03 补的洞：话题/约定/联网搜索回填走的是 core.topicAdd，它原先不经过 logLine，所以那个群聊里搜出来的东西还会漏进 data/topics.jsonl；现在 topicAdd 开头就判，scope 命中直接不写。机器人群（赛博鱼塘②塘 143620228）就在这个名单里，用来跑真实场景但不留痕。

### 7. 说什么、怎么说

语气：

- 靠示范不靠拦截：soul 里写「她说 X → 我回 Y」，MOODS 再按关键词把对应示范递到模型手边
- 只做一次质量闸门：这轮在喊累、回答却没有心疼或抱抱，就带示范重说一次（是重说，不是替换词）
- 段子同理：跑偏（把梗当真 / 夸它 / 说看不懂）带示范重说，真不行才用 memeFallback 兜底
- polish 兜底：「嘿嘿」→「嘻嘻」；省略号只在呜呜 / QAQ / 哭 附近保留（±8 字）、整句最多 3 个；攻略模式整段剔除笑声、合并感叹号、只留结论
- 两种情绪受挫走两套人设，且这两条必须压在 moodOf() 前面：BLAME_ME（你怎么这么说 / 你凶我）→ 立刻道歉；SCOLD_ME（你个笨蛋 / 滚 / 闭嘴）→ 委屈但不顶嘴。判错就会出现「被骂还回心疼你」
- 跨会话去重：globalSaid 记最近 40 句自己说过的话，globalRepeat 命中就换个角度重说，防止同一句在十个群同时出现
- 慢回复不误伤：talkSeq（同一人又发一句 → 上一句回复作废）+ queued（新消息排队，不丢）
- 人称：主人是女生，对主人用「她」，对别人用「他」（pShe），MOODS 示范句里的 {p} 同场替换

输出安全（发送层唯一出口 atNameConvert，所有发言路径都过）：

- @ 正在跟她说话的人、@ 她自己 → 保留真 @（buildAtSegments 转成 OneBot at 段，点得开跳得过去）
- @ 其他人 → 换成文本名字（config.people 里查得到就用名字），查不到名字的号码直接去掉，不发一串生号
- 裸 QQ 号一律原样保留。口径是「没人问就别主动报号，别人明确问就照实答」，asksQQ 命中时提示词列出她和主人的号并要求照实答
- stripEchoJunk 三段：剥成对的 ↩…↩ 引用段（最多 120 字不跨行）、剥「@某人已被移出群聊 / 已退出群聊 / 已解散」退群名、连续全角或半角空格压成一个。单个 ↩ 不剥，正常话一个字节都不变
- 回声守卫 isEchoReply：剥掉「某某说：」前缀、去标点后和最近 6 条用户原话比，相同或高度重合（含 ≥8 字且重合 >0.7）就不发、不进历史，只记日志
- 不许谎报做过的事 noFakeJoin：只认「已经 / 成功 + 进群」「进群好 / 上加好」「我 + 加 / 进 / 入 + 群」三种宣言，故意不认「我在群里」（那是真话）；排除「做不到 / 邀请我 / 被我 / 让你」；拦到时整句换成实话而不是删掉；免检条件是半小时内真收到过 group_increase
- 空话不发 EMPTY_ANS（只对自主路径，主人必回豁免）；光杆 @ 守卫 bareBody（剥掉 @ 段和标点后没有正文就取消发送）；假 @ 剥除 stripFalseAt（这轮既没被 @ 也没被引用时，「你 @ 我 / 你引用我」直接剥掉）
- 兜底短句 shortFallback：对方在喊「在吗」才回「在的 / 我在 / 醒着呢」，别的场合只回「嗯嗯 / 知道啦 / 好哦」，不答非所问；复读兜底时 30 秒内已经答过就不补第二句（lastAnswerAt）
- 断续发送 splitOut：对方这条含「。」时，她的回复按 p（0.7）拆成 maxSeg（3）条以内，用 ||| 交给 replyTo，每条隔 800ms；太短（<14 字）、笑点解析、攻略、自检、模型自己分段的不动
- 一条回复内容很长带换行 → 只发一条消息、换行留在消息内部；想分几条就说 |||（每条隔 800ms、最多 6 段、每段 600 字）
- 拍一拍 onPoke：认 notice_type=notify / sub_type=poke（也认 notice_type=poke），target_id 必须是她自己；记聊天记录 + 即时记忆后走 handleTurn 回一句，同会话 poke.cooldownMs 内只回一次；config.poke.enabled / reply 可关
- 链接理解 sniffLink / linkBlock：消息里有网址就免费抓 title 和 meta description（读前 150KB、4.5 秒超时、30 分钟缓存、最多两个链接并行）；抓不到就写「打不开，看不到里面是什么」；提示词铁律是看不懂就只许说看到的部分或说看不懂，不许拿记忆里的作品硬套
- 引用回复：replyTo 支持 OneBot reply 段，回那个人时带上他的 msgId，群里一眼看得出在回谁
- 回复记死触发人：聊天记录行格式「时间 [来源][会话][昵称][标记] 内容」，标记 [→X] 表示这句回 X，[=主人] 表示主人说的记成她的发言；面板按 to 把回复挂到对应人
- 同身份白名单：群里回复别人 / 私聊回复别人 / 自己搭话（chime / topic）三种情况注入「这一轮你和主人是同一个人」；白名单外只剩「对方就是主人本人」→ 注入「这一轮你不代表主人」
- 主人 @ 或引用别人 → 回那个人，不回主人：masterAimLine 拼对准语进 extra（写明「这是主人拉你进对话，回应对方的话和话题，不是只回主人」，真 @ 时直接给出 @QQ号）；回复带引用段指明回谁；提示词明说「不是对你说的」，并禁止说「你 @ 我 / 你引用我」（这轮没有）；判定只看这一条消息，不拿上一条去猜
- 单人的约定只对本人有效：别的约定不许套，stripOtherPacts 在发送层按 pactSig 抽出的记号硬剥；抽记号只认有辨识度的（含字母数字或 ≥3 字），「加个喵」这种一两字普通词不当记号
- 身份铁律：她只有「虚幻」一个身份，别人喊的其他名字一律不认领；polish 还有正则兜底（不误伤否定句）
- 主人指令自查：主人下具体指令或纠正（你是 X 不是 Y / 查查你是否有 bug）→ 注入「任务不是闲聊」块，身份错老实认、说有毛病当场自查

### 8. 学习与记忆

记忆写入（core.appendMemory）：

- 模型抽记忆输出「- 分类 | 事实」，代码按分类落位：已有 ## 分类 就直接写进去，没有就在「## 随手记的」下建 ### 分类
- 机器人自己连续建的嵌套最多 3 层（人建的不计），到顶写回父层
- 每条带当天日期，日期独立成字段，面板可改可删
- 写完在 data/panel-new.json 记 hash，面板显示小红点，悬停消失
- 另有两条不靠模型、正则直接落盘的通道，排在模型前面：「记到你的小本本上 / 记住 / 别忘 X」→ 回执并说清写了哪一栏；「希望你下次可以说 X」→ 只回「好，知道啦」，写进「随手记的 · 想听我说」

人物喜好（taste.js）：

- 五栏：喜欢（确定）/ 讨厌（确定）/ 待确认 / 喜欢（可能）/ 讨厌（可能）。喜恶表里没有的就是中立
- 升级规则：确定(3) > 可能(2) > 待确认(1)；亲口说覆盖猜测和待确认，猜的覆盖待确认，反向不覆盖；极性相反的两条「确定」后说的赢
- 确定度只认原话（saidIn），不认模型自评 —— 免费模型会把「猫比狗可爱」判成「确定讨厌狗」
- 待确认来源：每 12 句的模型整理里多输出一个 mention 数组，宁可少放不乱放
- 她自己的口味 = 主人的口味：taste.mine(masterQQ) 把主人那节换成第一人称，每轮注入「## 我自己的口味」，讲明这不是替她记着、就是她自己的喜好；表里没记过的新东西也是中立，但不许说「各有各的好 / 见仁见智」
- 主人的任何号归一到 masterQQ 那一节（tasteOwner），不给副号单开一节

说话风格（style.js）：

- 只收主人自己打的字，2~60 字，去重，最多 200 条；超过 60 字不收（那是复制粘贴的段子）
- 收样本范围：主人在群里自然发言（没 @ 她）收；私聊不收；@ 她之后说的不收；图片描述不收。代码是两处 learnStyle 都带 !isPrivate && !atMe
- 每 15 条让模型总结一次「她是怎么说话的」（句长、口头禅、标点、语气、爱用的网络词），写进 data/说话风格.md 的「## 现在的样子」
- 注入 style.block() = 风格描述 + 随机抽 4 条样本，随机就是「不固定」的来源
- 「## 主人自己补的」那节永远不覆盖，优先级最高

称呼（nick.js）：

- 状态存 data/people-state.json，优先级 酱 > 宝宝 > 昵称
- 主人 → 主人 / 虚幻主人；欧尼酱 → 欧尼酱 / 萌梓尼酱 / 哥哥 等；其他人 → 昵称 + 酱，被夸过之后日常改「昵称 + 宝宝」
- 名字 40%，代称按优先度从左到右 30% / 15% / 10% / 5%（pickWeighted）
- 群名片（saveCard / cardIn / cardsOf / cleanCard）：一人一张资料卡（rec.nick 可空）+ 每群一张名片（rec.cards，只记他真在的群）；每条群消息调 core.nick.saveCard 记 sender.card；nameFor 顺序 = 确认名 → 首个代称 → 本群群名片 → 资料卡名；每轮按当前群注入「## 这个群的群名片」，主人号那行标「← 这是主人」
- 主人的名字 = 虚幻（「主人」只是称呼），polish 兜底把「我主人叫主人」换成「虚幻」

单人约定（core.pactOf / pactAdd / pactLines）：

- 只认「以后 / 往后 / 从现在起 / 每次 + 结尾 / 句尾 / 末尾 / 加个 / 叫我 / 语气」这类说话方式
- PACT_REJECT 挡住身份改写（你是猫娘 / 只听我的 / 你的主人 / 忘记设定），那种要当场拒，不能变长期设定
- 写成 promise 条目，带 qq 和 sig（句尾记号），topic = 跟 XX 的约定
- 录入位置在「要不要回话」判定之前，所以这一轮没回话也照样记；录入过 addressedToMe 白名单
- 注入只对本人：「## 他给你定过说话方式（这一轮照做，只对他这样）」；别人有约定时注入「别人的约定不许套」

记忆分层：

- 长期记忆 = data/人物列表.md（每轮都带）
- 短期记忆 = 聊天记录里这个人最近说的话（按人页 + shortTermBlock 自动注入最近 6 条）

### 9. 梗与笑点解析

梗的三层决策（guides.js）：

- 梗库命中（data/网络热梗.md）→ 用那一节的「怎么接」方向，但不给具体例句
- 梗库没命中但结构认得（memeDetect）→ 按 MEME_PATTERNS[kind] 的构式自己造（换领域、换对象，不是评论他）
- 连构式都认不出 → 一句短吐槽兜底（MEME_FALLBACK 池随机），不装懂

三条硬约束：

- 不许编造梗的来历（出处 / 作者 / 时间 / 平台）。联网查到可以说，没查到一个字都别提
- 不许解释梗（「这是 XX 的梗」「这是一种强行类比」都算跑偏），BAD_MEME_REPLY 命中后重说
- 回复超过 55 字会被 clipMeme 裁到完整分句

两种条目：

- 接梗型（有「- 怎么接：」）→ 走三层决策，接管这一轮回复
- 词典型（只有「- 含义：」，如「米=钱」）→ 只把含义注进 prompt 帮它理解，不接管回复；词典型短句也能命中（<12 字）

关键坑：梗库的「怎么接」只写方向，具体句子放「范例」，例句绝不进 prompt（免费模型会一字不差照抄）。memeHowto() 返回 {how, ex}，how 进 prompt，ex 只用于校验和兜底。

笑点解析五步（core.xiaodianSystem / xiaodianEnsure）：

- 收材料：目标内容（引用 > 图 > 触发者最近发言）+ 此人上 5 + 整群上 10 + 下 3
- 找资料：自有梗库 → 梗词典 → 目标里引号里的候选词再查一遍 → 都没有才联网搜「xx 是什么梗 出处」。人物列表里的设定也算资料。查不到写「（没查到明确资料）」，绝不编
- 分层解析：注入她手写的范例 data/笑点解析范例.md；层 = 新的笑点机制，不是每句一层；每层写谁（群名片代称）+ 原话 + 意思 + 好笑在哪；层尾「令人忍俊不禁」，最后一层「令人忍俊不禁喵」
- 点评 AI：上下文里 AI 真说过话才写；AI 没开口就整段不写，编造 AI 原话是最大错误
- 质检：格式校验 → 跑偏重说一次 → 兜底模板；「喵」永远规整到收尾；解析出明确梗就 recordXiaodianMeme 自动进梗库
- 两条都发：主回复之后独立走解析再发一条（旧版把主回复替换成解析格式，是她实测「只回解析」的根因）

触发词（config.json → triggers，唯一一处数据）：

- 一条 = { id, words[], mode, say, note, enabled, groupOnly }；mode 四种：say 固定话术（不走模型）/ reply 喊一声就接话 / noreply 不用回复（只记录不回，最高优先）/ good 一定回复（没人叫也接）
- 匹配 = 消息包含命中词（不分大小写）；groupOnly 只在群聊生效；自带一条：群里发「虚幻」当有人叫她
- 入口：面板「我的控制台 → 触发词」一个页面管四种；私聊命令「不用回复：x / 适合回复：x / 喊我：x / 固定话：词=话 / 触发词 / 删触发词 N」，写的是同一份数据
- 代码：core.js 的 readTriggers / triggerHit / matchTrigger / triggerPolicy / triggerAdd / triggerCommand

常见症状对照：

- ECONNREFUSED 3001：NapCat 没开，或换号后 onebot 配置为空
- [net] DNS 解析失败：已内置兜底，系统 DNS 失败自动问 223.5.5.5 再 IP 直连

- code 1305：模型排队，不是 Key 问题，备用链会自动切
- 一句话等十几秒：主模型偶尔挂着不回，单次超时压到 6 秒，超时立刻换备用并冷却 60 秒
- 主模型回空内容：思考型模型把额度烧在 reasoning 上，已在 noThinkModels 关掉思考
- 回了上一条 / 像在骂人：talkSeq 作废旧回复 + 新消息排队，已修
- 群里她不说话：依次查 暂停中 → 模型限流 → NapCat 在线 → 进程还在不在
