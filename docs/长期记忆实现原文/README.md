## 三、一条规则放哪：判据原文摘要

摘自 `06_任务-维护记忆-归属与合拆判据.md`，顺序不能反：

1. **先看触发面**：不碰这件事就永远不会踩 → 放按需（`话题-X` / `任务-X`），**后果再重也不进常驻**。
2. **再看后果**：踩了不可逆（删错文件、泄露凭证）或要返工 → 常驻；只是答得糙 → 删或压成一句。
3. **禁用两条判据**：禁用使用频率；禁用字数阈值（2026-11-01 废除）。
4. **一条豁免**：≤ 30 字、踩了不可逆的硬红线可留常驻（触发识别一旦失败，按需文件等于不存在）。
5. **拆文件只在一种情况**：A 场景只读第 1 节、B 场景只读第 3 节 → 拆；永远整份读 → 再长也不拆。

三道闸防止记忆再变乱：**写前查**（先搜旧条目，有就改旧的）、**单一归属**（一条规则只有一个家，别处只写「见 X」）、**跑脚本**（`检查冗余.py`，报告里出现同一句两处就当场合并）。

## 四、虚幻侧怎么对应（2026-11-07 已落地）

| WorkBuddy | 虚幻 | 差别 |
|---|---|---|
| 用户级 `MEMORY.md` | `src/data/记忆/MEMORY.md` 的「## 每轮给模型看的」 | 每轮注入，只这一段，37 字 |
| 项目 `MEMORY.md` | `src/data/记忆/长期.md` 的「## 项目档案（不进提示词）」 | 只给人看，不占 token |

| 按天日志 | `src/data/记忆/日志/YYYY-MM-DD.md` | append-only；撤回 / 待修复 / 代码更新 / 手动记 4 个写入来源 |

| 名词解释 / 名词表 | 同一套 `xuhuan mac/名词解释/`、`名词表/` | 两边共用，不建平行文件 |

读写只走两个入口：`src/memory.js`（长期正本 + 按天日志）、`src/trace.js`（发言轨迹）。业务代码不直接读这些文件。

## 五、怎么核实「真在读 / 真在写」

- `node tests/test-persona.js` → 62 通过 / 0 失败，其中 3 条断言专门查「长期记忆真进这一轮提示词」「档案段不进提示词」。
- 客户端「聊天记录 → 工作日志」：按天读原文、切日期、手动记一条。
- 客户端「聊天记录 → 每条虚幻发言的推理」：看这一轮命中了什么场合、注入了哪些段、用了哪个模型、最后发了什么。
- 客户端「文件」页可直接改 `data/记忆/长期.md`，改完下一句生效（`mtimeMs + size` 热读，不用重启）。

## 六、推理那一栏的边界

模型是 `glm-4.5-flash`，默认关思考（`llm.noThinkModels`），不给 `reasoning_content`。面板「推理」展示的是**代码决策轨迹**（可逐条核对的事实），不是模型内心独白。没有思考原文时字段留空并写明「默认关思考，不是漏记」，不编。手动点「让她下一轮想给我看」拿到原文时，原样存入 `reason`，一个字不改。
